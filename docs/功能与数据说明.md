# 功能与数据说明

本文记录溯源的具体检索口径、数据处理方式和能力边界。安装与操作见 [使用说明书](../使用说明书.md)。

## 新闻与社媒研究库（RAG）

打开 `http://127.0.0.1:8000/library`。已有新闻研究中的**初筛合格正文**、浏览器剪藏、社媒帖子和导入的论文保存在 MySQL；启动服务或点击“从 SQL 重新建立检索索引”会同步到本机 `data/rag-index.sqlite3`。SQLite 索引用于加速检索，删除后可以从 MySQL 重建；原始论文 PDF 保存在 `data/papers/`，请和 MySQL 一起备份。问答先从本机索引提取新闻、社媒和论文证据，再调用配置中心现有的分析模型 API，回答附带原文编号、链接，论文证据另标页码。新材料要先运行新闻研究、采集社媒或上传 PDF；库内问答不会自动联网抓取。

社媒采集并行读取无需额外 Key 的 [Hacker News Algolia 搜索接口](https://hn.algolia.com/api)、[mastodon.social 公开话题时间线](https://docs.joinmastodon.org/methods/timelines/)和 [Lemmy 公开 RSS](https://join-lemmy.org/docs/contributors/04-api.html)。Lemmy 只取 world、china、technology、economics 四个社区各最新 20 帖，再按用户检索词本地过滤；每个 RSS 请求超时 5 秒，不是全站历史搜索。采集的原帖链接、作者、时间、文字及可得的互动数写入 `social_posts`。它们是可核查的观察样本，不能当作全网社媒覆盖或舆情声量。新闻、浏览器剪藏和社媒会在后台建立本地多语种向量索引；问答融合 FTS5 词面与语义召回，向量未完成或模型不可用时保留词面检索。Reddit 官方已宣布于 2026 年 11 月 13 日停止 RSS 支持，因此未接入免 Key Reddit RSS；本系统也未使用 GDELT。

### 融文全量记录下载（可选数据源）

研究库页面的“融文全量下载”使用项目内 [`meltwater-studio/ui/`](meltwater-studio/ui/) 源码；启动溯源时会自动启动本机 `127.0.0.1:8789` 的 Node 服务，无须另装研究台 EXE。需拥有可用的融文账号；当前 Chrome 账号需在 Chrome 的远程调试页面允许本实例调试，并打开已登录的融文页面。也可以点击“添加融文账号”，在独立 Chrome 窗口完成官方登录。账号管理显示连接状态与邮箱；邮箱优先从授权声明识别，无法识别时可以手动补填。未登录或连接失败的独立账号也可删除，删除时一并清理其独立浏览器资料。当前 Chrome 账号是系统入口，不能删除。已连接多个账号时可选择并行账号池。macOS/Linux 若使用非标准 Chrome 安装位置，可设置 `CHROME_EXECUTABLE`；当前浏览器资料目录可用 `CHROME_USER_DATA_DIR` 指定。账号元数据、浏览器资料与运行记录保存在已忽略的 `data/meltwater-studio/`，短时授权只在服务内存中，不随源码提交。缺少 Node 或融文账号时，其他研究库功能照常可用。

填写研究主题后可用配置中心的分析模型起草融文 Boolean 检索式，核对并修改后选择日期、账号和“仅新闻／全部类型”，点击“全量下载并入库”。单次日期跨度最多 370 天。内置融文研究台按月份分页下载；溯源只有在**平台命中数、导出行数和唯一文档数一致**时才将 JSONL 导出记录写入 `data/meltwater/`，再写入 MySQL 的 `meltwater_downloads` 与 `meltwater_mentions` 表。同一融文文档 ID 跨次下载合并，原始下载文件仍可逐次导出；本地 RAG 对标题与匹配片段相同的转载做去重。2026-11-24 用迁移后的代码和当前已登录账号测试单日新闻查询 `"China" AND "rare earths" AND "Argentina"`：平台命中 2 条，下载 2 条、唯一记录 2 条，新增入 MySQL 2 条。另用 `China` 做单日预览，显示平台命中 96,371 条并取回前 25 条。测试验证了启动、账号识别、检索、完整性检查和小样本入库，不代表平台覆盖率或大规模下载速度。

当前融文研究台的导出字段含标题、日期、来源、URL、类型、语言、国别、情感和**最多 280 字的匹配片段**，不等于文章全文。有效片段进入本地检索索引时标为“融文匹配片段（非全文）”；付费增值权限导致标题或正文被平台遮蔽的记录只保留计数和元数据，不作为全文证据。平台情感是文本极性，不能直接等同政治赞否；国别字段是来源所在地，不代表受众国籍。融文下载独立于 DeepSeek 的 30–50 篇长篇代表材料筛选，不会把片段冒充可逐段核验的完整新闻。

### 导入论文 PDF

按“运行”一节在项目 `.venv` 安装依赖。在研究库页面选择或拖入一份不超过 **15 MB、150 页**的 PDF。系统优先提取可复制文字；扫描页由本机 RapidOCR 识别。若勾选“多模态补救”，仅在本地 OCR 字数或置信度不足时，把该页图片发送给配置中心的分析模型 API，最多 12 页；模型需要支持图片输入，这一步可能产生 API 费用。标题、作者、年份可手填；留空时依次使用论文网页元数据、DOI 的 Crossref 书目、PDF 内嵌元数据及首页文字。自动识别结果应在研究库核对。正文、页码、识别方法和书目来源写入 MySQL `paper_documents`，原 PDF 存于本机 `data/papers/`；完全相同文件按 SHA-256 去重。不开启多模态时，PDF 页面图片不会发送给分析模型；**问答时命中的短证据段落**仍会发送给配置的分析接口。

后台使用 [FastEmbed 支持的多语种 MiniLM 模型](https://qdrant.tech/documentation/embeddings/fastembed/)在本机为论文段落生成 384 维向量，并与段落、页码一同保存在本地 SQLite 索引。首次向量化需要从模型仓库下载约 220 MB 模型文件至 `data/embedding-models/`，以后离线复用。下载或向量化失败时，PDF 和正文仍已入库，论文可用词面检索；页面会显示状态并允许重试。论文的向量召回不代替对其研究结论、发表时间和适用范围的人工核验。

两篇结论相反的论文作为两份独立文献保留；当前只对完全相同的 PDF 文件做 SHA-256 去重，不按观点合并或覆盖。问答最多取 8 条论文证据，每篇最多两页，同一页只取一段，并要求分析模型并列呈现检索到的相反主张和页码。研究时间、样本、方法等差异仅在摘录明确包含时才可用于解释分歧；证据不足则标为未决争议。**论文结论尚未建立逐条关系索引，上传时也不会自动发现所有冲突**；问答没有检索到反方材料，不代表反方不存在。

### 主张档案与人工核验

把研判档案保存为每日监测后，系统给每个风险主张分配稳定的本地编号。每次更新记录本轮支撑和反向材料、语种原文摘录、模型风险估计及相对上次的新来源；没有再次出现的主张标为“本轮未重现”。标题相似度和已引用 URL 用于自动关联，关联结果须人工核对；“最早材料”仅指本库已采到的最早一篇，不能断言全网首发。模型可提示原文跨语种语义差异，但没有足够原文时留空。

研判档案新增证据核验工作台。每条被风险点引用的原文段落可标为“已核实／有争议／不采用／待核验”，填写备注并写入 MySQL `evidence_reviews`；原文发生变化时提示重审。有争议或不采用的支撑段落会在风险点旁标警示，原始模型分数仍留作审计记录，不自动改写为人工结论。

## 浏览器辅助导入订阅文章

如果文章在你本机 Chrome 或 Edge 中经已有阅读插件处理后可以正常阅读，可以使用项目自带的 `browser-extension` 把**当前标签页可见的正文**导入本地研究库。它不会读取浏览器 Cookie 或账号；导入前可编辑标题、媒体、日期、语种和正文。DeepSeek Search / Fetch 仍负责全网检索与公开页面抓取，浏览器导入用于补全你已能阅读的材料。

1. 启动 Demo，打开 `http://127.0.0.1:8000`，找到“导入浏览器可见正文”，复制配对码。
2. 在同一个浏览器打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选中本项目的 `browser-extension` 文件夹。
3. 打开目标文章，确认浏览器已显示正文，然后点击“溯源 Clipper”扩展图标。首次使用在“连接设置”中粘贴配对码，点击“测试连接”；成功后会记住设置。以后弹窗会自动预览清理后的正文并尝试识别发布日期，点击“保存到溯源”即可。若日期未识别，仍可保存并标记为“发布日期待核”；若正文提取不完整，展开“检查与修改内容”调整或重新读取。
4. 返回溯源网页，导入列表会自动刷新；勾选要加入下一轮研判的文章并启动任务。点击扩展中的“保存到溯源”时，文章立即写入 MySQL 的 `browser_clips` 表并关联新闻主库，不必等待研判任务。系统仍会按检索时段、篇幅、体裁与同稿规则筛选；通过筛选的材料可进入观点与风险点分析。数据库暂不可用时文章先保存在本机 `data/browser-imports.json`，重新连接数据库或重启服务后补入。

更新了项目文件后，请在浏览器扩展管理页点击“溯源 Clipper”的刷新按钮，加载新版弹窗。

论文 PDF 统一采用手动选择文件入库：先在论文网站正常下载 PDF，再打开“溯源 Clipper”，在“论文 PDF 入库”区域选择文件并点击“识别并入库”；也可以在网页研究库 `/library` 上传。扩展不再检测、请求或抓取论文网站的 PDF 下载地址，也不再申请任意论文网站的下载域名权限。若当前网页有论文题录元数据，扩展会附上标题、作者、年份、DOI 等信息；没有时由本机 PDF 解析和 DOI 查询补充。扩展保留原有 DOI 外部跳转功能，但该跳转不会自动下载或入库 PDF。

关于你提供的 Bypass Paywalls Clean：其源码采用 MIT 许可，完整扩展含大量按站点维护的请求头、Cookie 和网络规则。溯源 Clipper 此次采用独立实现的当前页 JSON-LD 正文提取，没有复制该项目代码，也没有要求其全站权限。它不能保证取得服务端未向浏览器发送的付费全文；这类文章仍由你当前可用的阅读方式打开后导入。

浏览器导入只处理你明确选择的当前文章，不会批量调用已有插件。Clipper 参考 Obsidian Web Clipper，集成了 MIT 许可的 [Defuddle](https://github.com/kepano/defuddle) 本地浏览器包，优先提取文章主体并去掉页眉、导航、推荐区和页脚；保存为纯文本时保留文章内链接的文字，不附带链接地址。发布日期依次从页面元数据、JSON-LD、正文时间元素和 URL 中识别，无法确认时保持空值，不把剪藏时间当成发表时间。日期未知的剪藏仍可入库和检索，但在限定时段的研判中会标为“日期待核验”，不会自动入选分析。提取器失败时会尝试清理文章 DOM 和页面自带的 JSON-LD 正文；服务端未提供全文时仍需通过正常阅读方式取得文章。来源、发布日期及使用权限由导入者核对。第三方许可见 `browser-extension/vendor/DEFUDDLE-LICENSE.txt`。`data/browser-imports.json` 是 SQL 的本地后备，和配对码文件均已从版本控制排除。

## 分析接口配置

配置中心的“分析模型 API”可填写 **OpenAI 兼容**或 **Anthropic 兼容**格式的服务链接、API Key、Model。服务链接可用基础地址（例如 OpenAI 兼容 `https://服务地址/v1`、Anthropic 兼容 `https://服务地址`），也可填完整的 `/chat/completions` 或 `/v1/messages` 地址。点击“获取模型”会调用服务的模型列表接口；若套餐网关不提供列表，可手填模型标识。思考强度使用所选接口的官方参数；若模型列表返回了支持档位，页面会据此收窄选项，否则显示接口格式的官方档位。先“测试连接”，再“保存并启用”；测试会消耗少量模型额度。

启用后，**DeepSeek 只负责 Search / Fetch**；检索式规划、入选体裁与原发筛选、风险点研判全部使用选定的分析接口。若未填写，继续沿用 DeepSeek 模型做分析。可以在网页恢复默认分析。配置仅存于本机 `data/analysis-config.json`，API Key 不会返回网页；更换服务链接时必须重新填写 Key。

在配置中心“SQL 入库”填写运行该 Demo 的电脑上的 MySQL 主机、端口、库名、用户名和密码。先点“测试连接”，再点“连接并建库”。程序会创建 `suyuan` 库（可改名）、`research_runs`、`news_articles`、`article_master` 和 `article_aliases` 表，并把已有 `data/records.json` 导入。`news_articles` 保留本轮全部候选及入选／排除状态；跨任务重复报道通过 `article_master` 只保存一份全文，原站、公开转载和快照链接记录在 `article_aliases`。后续研判会同时保留 JSON 本地备份并写入 MySQL；页面会标明入库成功或失败。连接密码保存在本机 `data/mysql-config.json`，该文件已从版本控制排除，建议使用专用数据库账号。MySQL 实例、账号和数据不会随 GitHub 代码自动迁移。

网页打开时会自动读取 MySQL 中最近的研判档案；点击档案可查看风险判断、每个风险点对应的原文段落、主要观点、样本趋势、入选新闻和全部候选。数据库暂不可读时，页面会明确提示并展示本地 JSON 备份。新任务完成后，档案与新闻列表会立即更新。

## 统一检索标准

每一次研判采用多语种、分时段检索口径：默认分别检索英语、西语、德语、法语、俄语、阿拉伯语、葡语、韩语、日语九种语言，每种两组检索式，共 18 组；可填自定义语种覆盖默认清单（最多 12 种），也支持中文、泰语。越南语已从当前可选语种移除，旧监测任务下次运行时会自动过滤该语种。未指定时间时检索近 40 天，输入“2026 年 10 月”或填写日期可指定最多 45 天的窗口。检索式由当前分析模型用对应语言生成，程序补上语言及日期条件；Search 请求最多四路并行，按完成组数显示进度，并记录每种语言的查询、候选、提取、初筛及失败数量。九语种比原六语种增加 API 调用量；关注特定地区时可自定义较小的语种集合。工作台的默认语种说明从 `/api/search/languages` 读取，以服务端实际配置为准；静态页面和脚本响应不缓存，更新后刷新即可看到新说明。

DeepSeek Search 每组检索式最多返回 50 条；本程序请求 50 条，触及上限时自动将时段二分并继续检索，直到结果不再触顶或缩到单日。单日仍触顶会显式标记“可能未穷尽”。**全量指本轮检索式及可拆分日期窗口内接口实际返回的候选，不等于穷尽全网。** URL 合并后逐条 Fetch，所有候选连同入选或排除原因都写入 MySQL。程序按日期、可读正文与篇幅过滤（拉丁文字至少 3000 个非空白字符，中文、日文、韩文至少 1600 个），再让当前分析模型按体裁和原发属性初筛；纯通讯社通稿、短讯、聚合转载和事件复述不进入代表材料池。跨站同稿在文章主库去重。最后综合检索相关度、权威来源、语种、媒体和日期覆盖，从合格池选最多 50 篇代表材料，至少 30 篇为达标。分析模型归纳主要观点与分歧，再提炼至少 4 个风险点，每点引用至少 4 篇不同报道及其真实原文段落。数量或风险点不足时标为“待补”。

权威媒体原站优先进入候选队列；原站无法取文时，对 Reuters、Modern Diplomacy、The Diplomat 等来源尝试公开历史快照和注明原媒体的公开版本，保留原始 URL 与实际取文 URL，多个版本仍只算一篇。达到数量和结构门槛也只表示自动初筛达标，首发、作者、原文语种及快照来源仍须逐篇人工核验。较长检索在后台执行，页面用阶段进度条显示检索、抓取、筛选、研判和入库，刷新后可恢复当前任务。旧版档案会在页面标为“旧版记录”。

## 每日增量监测与趋势

打开一份档案，选择每日重跑时间并点击“保存为每日监测”。本地服务持续运行时会按北京时间自动检索；也可以在“每日监测议题”中立即增量更新或暂停。增量任务从上次检查日前两天开始补检，并跳过该议题已见过的 URL；新入选代表材料与上次材料合并，仍按 30–50 篇和 4 个风险点研判。页面显示新增材料、候选新风险点、发布日期分布、语种和主要媒体构成。单次新增代表材料达到 5 篇或出现候选新风险点时，在本机页面提示复核，不会自动向外发送消息。监测配置保存在 `data/watches.json`，已从版本控制排除。关闭本地服务期间不会执行计划任务，下次启动后会补跑已到期议题。

## 数据与合规边界

- DeepSeek Search 发现候选链接；DeepSeek Fetch 提取可公开访问的正文。
- 原站遇到订阅、登录或访问控制时，不提交账号或 Cookie。系统可查询 Internet Archive 的最新公开 HTML 快照；对优先来源直接提取可读的公开快照正文，或者寻找注明原媒体的公开转载版，并标明取文路径。DeepSeek Fetch 对快照 URL 返回 404 时仍可尝试本机直接读取。
- 没有取得正文或未通过长篇原发筛选的快照与转载只作为线索保存，不计入30篇或风险点证据。
